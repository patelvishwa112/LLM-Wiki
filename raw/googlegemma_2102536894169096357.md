## Linked article

Source: the linked repo, `github.com/taeold/djev-run` (README fetched 2026-10-24; Apache-2.0, 584 stars, 64 commits).

**What it deploys.** A `vllm serve` container for `nvidia/diffusiongemma-26B-A4B-it-NVFP4`, the NVFP4-quantized 26B-total / 4B-active diffusion Gemma checkpoint (built on `mmastrac/djev`), onto one NVIDIA RTX PRO 6000 Blackwell GPU via Cloud Run, exposing an OpenAI/`djev`-compatible API plus demo apps at `/snake`, `/dino`, `/tetris`. Supported RTX PRO 6000 regions: `us-central1`, `europe-west4`, `asia-southeast1`, `asia-south2`.

**Setup path (3 steps).** (1) Create a GCS bucket, `hf download` the weights, `gcloud storage cp` them up. (2) Deploy either the prebuilt image `ghcr.io/taeold/djev-run:latest`, or `docker.io/vllm/vllm-openai:nightly` with no custom Dockerfile and the engine flags passed as `--args`. (3) Query with `curl`.

**Deploy flags that matter.**
- `--gpu=1 --gpu-type=nvidia-rtx-pro-6000 --no-gpu-zonal-redundancy`, `--cpu=20 --memory=80Gi`, `--concurrency=32`, `--min-instances=0 --max-instances=1`.
- Weights mounted via `--add-volume ... type=cloud-storage` + `enable-buffered-read=true`, then `cp -r /mnt/gcs/dgemma /dev/shm/dgemma` so the ~18 GB of safetensors are prefetched into RAM before the engine starts; GCS streaming measured at ~1.05 GiB/s over Google internal networking.
- vLLM knobs: `VLLM_ENABLE_V1_MULTIPROCESSING=0` (in-process EngineCore, avoids double-importing Python/CUDA), `VLLM_FLASHINFER_MOE_BACKEND=masked_gemm` (low-latency FlashInfer MoE kernel for Blackwell SM120), `--enforce-eager` (skip `torch.compile` + CUDA graph capture), `--language-model-only` (skip the unused SigLIP vision encoder), `--kv-cache-memory=2G` (skip startup memory profiling), `--attention-backend=TRITON_ATTN` (Triton bidirectional attention required by diffusion), `--diffusion-config '{"canvas_length":128}'`, `--max-num-seqs 32`, `--max-model-len 4096`.

**Performance claims.** Cold start from zero instances ~47.5 s, down from a 4 m 05 s baseline. Median 61 ms server-side, 117 ms end-to-end at `steps=1, samples=1` (121 ms with `samples="auto"`). Batch throughput ~100–123 req/s at `concurrency=32`. On JevBench v1.3.0 (N = 231 public suite): 81.4% overall accuracy / 73.4 composite at 117 ms, 81.8% / 73.5 at 121 ms, versus the hosted `api.djev.dev` at 81.8% / 73.0 in 237 ms.

**Cost.** 1× RTX PRO 6000 (20 vCPU, 80 GiB RAM) at **$3.19/hour** while active, scaling to $0 when idle with `--min-instances=0`.

**Diffusion read API.** `/v1/chat/completions` accepts `vllm_xargs` with `diffusion_seed_canvas`, `diffusion_pinned`, `diffusion_max_steps`, `diffusion_read_only` — i.e. you can seed a partial answer and fill it. A `/v1/systemone` endpoint returns multiple-choice answers with per-option probabilities (`{"billing": 0.942, "technical": 0.041, "account": 0.017}`, `confidence: 0.942`, `total_ms: 116.3`) in a single diffusion pass.
