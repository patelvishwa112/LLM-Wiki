Skills, what are they good for?

Why no one agrees on skills, how to think about them, and cool ones we use daily. 
There's a certain type of AI user that thinks skills are pointless. Just tell the agent what you want and it can figure it out. No need for complicated frameworks. The labs are distilling all the public skills into their models anyway, so over engineering what is basically just a prompt feels useless. 
From @mikedevs
Then there are people like Garry Tan who are a big proponent of building and maintaining skills as a form of natural language code. They think skills are the next big thing. These people might respond: War and Peace is also "just a prompt".  
People on both sides of the aisle are smart, so what's creating this difference? The answer lies in developing clear answers on 1) what is a skill exactly? and 2) what problems do skills actually solve? As we'll see, those that dismiss skills have a narrower definition of what skills actually are compared to reality. 
What is a skill exactly? 
The wrong way to think about skills is that they are just a markdown file. That may have been the original intent, but they have since developed into much more than that. This means that the boundaries between what is a skill and what is not a skill has become unclear. 
Here are three examples that test the limits of where a skill begins and where it ends: 
Last30days - is a skill that keeps you updated on the comings and goings of HackerNews, Reddit, X, etc. This resembles less a traditional skill and more a mini-program that is executable by agents. Beyond markdown files, it includes code and tools for the agent to call.t
Symphony - This is just a markdown file. However, it contains the full spec for a multi-agent orchestrator where the recommended installation pathway is to have codex build it from scratch. Here, we see that a markdown file isn't just a markdown file. Some of Andrej Karpathy's viral skills like his LLM Wiki also fall into this category. They become schelling points for a class of products, all built custom to each user. 
Plugins - They contain not just skills but also things like hooks and tools which all integrate with agent harnesses at different points. Claude Code, Hermes, and Openclaw have some of the more developed plugin eco-systems. There are genuinely things you can do with a plugin that you cannot do with a raw skill. 
The general definition of skills then, is that they are folders of information which help an agent perform tasks. This is intentionally vague because a skill is not a cleanly defined object. However, this turns out to be enough to say quite a bit about how they're used.
What problems do skills actually solve?
On the surface, skills don't do much that you cannot do in a prompt. This is true at the individual user level. However, skills make much more sense when you zoom out and look at it from the perspective of building systems. There are four areas that they help with:
1. The recall vs recognition gap. 
This is the same problem that GUIs solved compared to the terminal window. There is nothing that a GUI can do that a terminal cannot, but it is hard to remember terminal commands. More importantly, a user may not even know what is possible when faced with a blank terminal. A GUI solves this problem by clearly enumerating what actions can be taken, turning a recall problem into a recognition one. 
We find the that the coolest skills do much the same: they show us cool things we can do with agents that we hadn't even thought of before. Here are a couple of examples:
Youtube lecture notetaker  - extracts lecture slides from YouTube videos and enables you to add your own notes to them while watching the video
3D Graphic skills - as someone who is not a 3D designer, I wasn't aware this was even possible with agents until the skills showed me the way
WYSIWYG HTML editor - We created a skill to edit and remove AI slop directly on the page itself. Makes AI slides feasible because you can then go and wordsmith them yourself after the layout is done.
Record and reply - record a loom video, convert that into a skill
2. Consistency
Agents tend to be wildly inconsistent. It may take the right path most of the time but occasionally end up down an irrecoverable rabbit hole. Skills solve this problem by providing standard SOPs in cases where there may look like there is more than one way to complete a task. These SOPs can then be refined and pushed out to every agent. Think of them like a pilot handbook. For critical or frequent tasks, we don't want the agent to be rediscovering things on the fly. 
The most common ones in skill libraries like Clawhub tend to be of this type. Specifically, they tend to tell agents how to integrate with external sources. Without them, integrations can be a bit flakey (e.g. I've seen an agent ignore a MCP and go create an API key for itself with computer-use instead). 
3. Portable Expertise
These skills solve the problem of a specific set of expertise that the user may not have: cybersecurity, design, SEO, etc. Think of these as O'reilly how-to books for agents.

4. Reasoning Checkpoint
These are personalized skills which accumulate specific knowledge about a user over time. For example, we have one that helps us automate email scheduling for sales outbound. These skills are inherently personal since they conform to the exact working style of the user. The key is that they represent a consolidation of information from both previous agent traces as well as user feedback. 
How to build good skills 
Overall, skills enable us to compound and scale agentic systems in token space. It's not enough that models are intelligent. They also need the procedural knowledge and context of how to work within a larger system. Skills provide that bridge. In this way, they are an early form of memory. Thus when you build skills, you should think less about what problem they solve for you right now but about what problem they solve for the system at large, whether that's your team or you in a week's time. 
There are two frameworks that are useful here:
First, skills are essentially just markdown files (the nuances above notwithstanding). This means that the generations of effort we have put behind organizing and structuring text comes into play here, such as how to write clearly or procedures for proofreading.
Second, continuous improvement over skills fall prey to the same Goodhart's law problems as normal machine learning optimization. And often times, the solutions are the same. In particular, many of the regularization techniques that work in training neural networks also work for skills! A few examples are backdrop, evolutionary search, gradient clipping, and dropout.
