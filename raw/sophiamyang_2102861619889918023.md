TL;DR
This toy task demonstrates how to train Qwen3.8 27B to write less AI slop using RL on Fireworks with Jev as the reward model. After 24 updates, the mean Jev reward went up from 0.583 to 0.759, showing evidence for a less AI slop output according to Jev.
Jev can significantly reduce the latency and cost for a RL training: 896 calls cost $0.061 with median latency 186ms.
Fireworks makes Reinforcement Learning training straightforward and easy to start. Everyone can run their training jobs on Fireworks.
Run -> Code Tutorial 
Disclaimer: this blog and demo is for demonstration purposes only with the hope that you can get started running your own RL runs with this toy example.
Context
Jev is a new model released by TypeSafe: “Think of Jev as a frontier-intelligence function call: unstructured state in, typed probabilistic decisions out.” It’s extremely cheap and fast to make decisions and classifications. I’ve seen a lot of people using Jev to classify texts especially tweets and flag AI slop (quite fast and useful use case I’d say). That made me to want to try use Jev to provide training feedback in an RL experience to see if we can actually train a model to produce less slop by Jev standard.
The RL process
Base model: Qwen3.8 27B
What we are training: a rank-8 LoRA adapter, which means a very small set of parameters we train that can add on top of the frozen base model. The base model never changes during the training. We only train on the LoRA adapter.
Training prompts: 96 AI-generated prompts covering posts, summaries, edits, replies, and creative writing, and often with some context (yes as you can see this is a toy example and we are not covering everything - this is a limitation of this example if you are wondering).
Rollouts: For each prompt, the policy (Qwen3.8 27B with LoRA adapter) generates 8 rollouts (i.e., drafts or outputs).
Scoring and reward: Each rollout/draft gets scored by Jev and the scores get calculated into a reward score (see more details below). Each rollout is compared with each other - the ones above average get reinforced and the ones below get discouraged during training.
Policy updates: every update uses four prompt groups, which means we do 24 updates to pass through the whole 96 training prompts.
Evaluation: we have 24 held-out prompts that we saved for evaluation. The base model and trained model each answer these 24 questions, and then their outputs get scored by Jev.
The reward
Let’s take a closer look at the questions we ask Jev.
Style: Does this read naturally rather than like generic AI slop?
Quality: Is this useful, high-quality writing for the request?
Source support: Does it add material claims unsupported by the context? (note that the answer “no” here means source support)
Jev returns probabilities to each of these questions, which we then used to calculate the reward score. Here is a high-level calculation:
reward = ((style + quality) / 2) *  source support
As you can see, we are optimizing for Jev telling us the model outputs good style, quality with source support. We are optimizing for Jev’s responses, not whether output is actually better. We are trusting Jev here!
More technicality Under the hood. Each draft's advantage is its reward minus its group's average, divided by the group's standard deviation (floored at 0.1) and clipped to ±3. Groups with almost no reward spread are skipped. The loss is unclipped importance sampling, each draft is weighted by one over its length, and a KL penalty (β = 0.05) keeps the model close to the untrained version. This is GRPO-style (group-relative advantages) without PPO clipping, but I'd change a few things in a bigger run. Dr. GRPO shows that dividing by length favors shorter outputs, which might explain some of our length drop. And because Jev scored both training and evaluation, a second judge or some human ratings would make the results much more convincing. The KL penalty stops the model from drifting too far, not from gaming Jev.

Most of the increase in reward comes from source support, followed by style, while quality didn’t change much (quality was already good near the ceiling!). The training helped the model learn not to add unsupported claims.
The output got a lot shorter (about 40%). Jev actually seems tend to think shorter outputs as less sloppy, which is sort of expected since they make fewer claims and the length normalization favors short outputs. We could investigate results further by length and If we do not want this behavior, we could add a penalty for a capped shortness.

After you finish training, you can save your final model in your fireworks account and see it under https://app.fireworks.ai/ → Custom Models, where you can deploy your model there easily on a dedicated deployment. You can also download the adapter via API and then put on your HF to share : )
Final words
Jev probabilities are useful, but not truth. Use cautiously. (Interestingly, sometimes Jev and Astra disagree).
Watch the length drop and the word omitted.
This demo shows Jev can be used nicely as a reward model to drive Fireworks RL. We have not made a universal anti-slop model. RL with Jev alone might not be enough to produce a solid universal model. Other techniques might be needed to help to move the needle! In fact, our team has a much larger run with more careful calibrations on that we will share very soon. Stay tuned!
