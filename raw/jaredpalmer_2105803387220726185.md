## Linked article

Source: `https://t.co/53wZQYhPc2` resolves to the GitHub repository
[jaredpalmer/kev](https://github.com/jaredpalmer/kev) (Apache-2.0, ~9.5k stars, 350 commits; README read 2026-10-24).

Kev is a family of small "decision models" — models that answer a batch of yes/no, multiple-choice and
rating questions about one piece of text — built on Qwen3.5 and Qwen3.8, following the architecture
described in Archer Hume's write-up "Jev's Architecture Unmasked." The API mirrors TypeSafe's hosted
Jev "System One" API, so TypeSafe's Python SDK can be pointed at a local Kev server unchanged.

**What it returns.** One request carries a `state` (the text to judge: string, object or array) and a
set of questions, each `noul` (probability of yes), `choice` (1–255 named options, with `probabilities`
and `confidence`) or `score` (1–255 ordered levels, answered as a mean level index plus a distribution).
Questions share the state but cannot read each other. Every checkpoint ships with a fitted temperature,
so probabilities are calibrated out of the box. Confidence is `(p_max − 1/K)/(1 − 1/K)` for choice and
`max(0, 1 − E|level − mode|/D)` for score — TypeSafe's formulas, not measured accuracy rates.

**Models.** Four sizes released together as Kev 1.0, each Hub repo tagged `v1.0`: Kev-0.8B (Qwen3.5-0.8B-Base,
runs on any 4 GB GPU, or any Apple Silicon Mac), Kev-4B (L40S/H100), Kev-9B (L40S/H100), and Kev-27B
(Qwen3.8-27B post-trained, B200/H200/H100 80 GB, ships as 51 GB of full weights rather than an adapter).
0.8B/4B/9B are a small adapter on a frozen base; 27B fine-tunes every weight. Validated context is
8,192 tokens for the three smaller models and 65,536 for Kev-27B (longest document where accuracy on
real contracts stays within 3 points of 8k).

**Benchmarks.** On `breadth-v1` (14 public datasets in five areas none of the models trained on),
chance-corrected index: Kev-0.8B 23.3, Kev-4B 38.0, Kev-9B 41.0, Kev-27B 52.3, against hosted Jev's
54.0. Accuracy on new sources (development/test): 0.648/0.697 (0.8B), 0.817/0.838 (4B), 0.820/0.852
(9B), 0.851/0.889 (27B), Jev 0.857. Brier on new sources: 0.481/0.416, 0.269/0.242, 0.289/0.217,
0.225/0.156, Jev 0.211 — lower is better. At a 5% error budget the 4B/9B/27B automate 0.52–0.69 of
new-source decisions, the 0.8B 0.14, Jev 0.70. Kev-9B puts ≥0.9 probability on a wrong answer for 2.4%
of new-source questions versus Jev's 3.7%. On MMLU Kev-9B scores 0.73 and Kev-27B 0.90; on MMLU-Pro
Kev-27B scores 0.675 against Jev's 0.840 — knowledge tracks the base model, not the decision head.

**Speed.** Kev-4B answers six questions about a new short text in 18.1 ms of model time on an H100 and
41.5 ms on an L40S; its in-process server handles ~101 req/s on an H100 before HTTP overhead. On an
Apple M5 it takes 721 ms for five questions, or 136 ms when the text repeats and hits cache.

**Fine-tuning.** `--init_from` loads the released adapter and pointer head, so a short fine-tune keeps
what Kev knows: on an example support workload (three questions, 1,050 generated records, 15 minutes on
an H100) Kev-4B went from 67.7% to 73.6% accuracy and from automating 34% to 48% of decisions at a 5%
error budget; one epoch on 5,219 labelled consumer-finance complaints took it from 0.804 to 0.904 on
unseen complaints. Starting from the base model instead throws that away: one user's test on 836
support-tool decisions scored 0.33 on Kev's eval set from base, against 0.84 for the released model,
while the same data with `--init_from` kept 0.83 and reached 0.88 on the new domain. With 400 records
the gain was inside the noise. A Kev-4B training run costs about $1 on an H100.

**Serving.** `uv sync --extra serve` then `python -m kev.serve --run jaredpalmer/kev-4b --port 8009`
runs locally on CUDA/ROCm or MLX on Apple Silicon; a Modal deploy gives an HTTPS endpoint that scales to
zero (first request after idle waits ~35 s). A coding-agent skill (`npx skills add jaredpalmer/kev@kev-finetune`)
runs the whole loop: interview, find the questions, label or generate data, fine-tune on Modal, fit the
temperature, score against the untouched model, deploy, tear down. A `kev-deploy` skill does the endpoint.

**Caveats.** `pip install kev` is a different package (K.E.V. ORM) — this project is installed from
source, Python 3.12/3.13 only. Long-document reads at 32k OOM on 4B/9B. The repo's own notes record
eval suites removed as unsound gates (WANLI pairs where annotators disagreed; a typesafe-v1 gold set
whose split-half r across 20 checkpoints was −0.01).
