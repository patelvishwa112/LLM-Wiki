### The historical ladder (IMDb movie-review benchmark, balanced)

| Approach | Accuracy |
|---|---|
| Bag-of-words + logistic regression | 89.9% |
| LSTM RNN trained from scratch | 85.66% (substantial overfitting; RNNs hard to train) |
| Text CNN (global max pooling) | 90.07% |
| ULMFiT (pretrained then fine-tuned, 2018) | 95.4% |
| ModernBERT (2024) fine-tuned ~23 min | ~95% with minimal hyperparameter tuning |

Raschka still recommends bag-of-words + logistic regression as the default baseline for any text-classification problem — it is cheap, and the models it feeds (naive Bayes, logreg, SVM, XGBoost) expect a fixed-size vector, which the vocabulary-count representation supplies. Its weakness is losing word order ("the dog bites the man" == "the man bites the dog"); n-grams partly recover local order at the cost of vocabulary growth. Text classification with naive Bayes dates to at least 1961 (sorting computer abstracts); Gmail's original spam filter allegedly used the same setup.

Transformer route: BERT-style encoders are natural classifiers via the `[CLS]` token; decoder-style GPT models can also be repurposed by swapping the vocabulary-sized output layer for a lean classification head (must mind the autoregressive attention mask so the classification position can see the whole sequence).

### What Jev is

Jev is a proprietary model from TypeSafe AI, positioned as on par with GPT-5.6 Luna on decision-making while being orders of magnitude faster and cheaper. Raschka calls it "the ChatGPT moment for classification" — a general-purpose classifier that does not need per-task fine-tuning. Three API shapes:

- **Choice** — multi-class; returns `choice`, `confidence`, and per-class `probabilities`.
- **Noul** — a single "yes" probability per question; probabilities across questions need not sum to 1, so it suits binary and multi-label work.
- **Score** — ordinal, scored against rubric levels (e.g. 0/1/2).

Example request shape (Choice, model `jev-1.13.0`): `state` holds the text, `questions.<name>.criteria` maps each label to a description; response returns `confidence: 1.0`, `probabilities`, and `usage` token counts (342 in / 32 out for one review). The same review through Noul returned 0.98 rather than 1.0 — the two APIs are not interchangeable numerically.

### Measured results (25,000-review IMDb test set)

- **Choice:** 96.47% accuracy (24,117 correct), 22 min 24 s, 15,456,663 input tokens, **$0.6492** total.
- **Noul:** 96.20% (24,050 correct), 23 min 3 s, 15,106,663 input tokens, **$0.6345** total.
- **ModernBERT reference:** 23 min to fine-tune, 7 min to evaluate, comparable accuracy (run on a DGX Spark; quantization/faster hardware would speed it up).

Runs are not fully deterministic — a repeat Choice run gave slightly different numbers (batch-dependent GPU kernel ordering changing floating-point operation order). Caveat Raschka notes: it is unknown whether the IMDb test set was in Jev's training data.

### Building a Jev-like API yourself

Add a head with **one** output node (not one per class) to a BERT/GPT/T5 model; for each candidate label, feed the model the text, the task instructions, and that candidate's description, and let the shared head emit a scalar score `s_i = w·h_i + b`. Softmax over the N candidate scores gives a distribution; the same weights work for any N, so class count and descriptions can change without changing the architecture. `h_i` is the `[CLS]` final hidden state for encoders, or the last non-padding token's hidden state for decoders. Raschka built such a ModernBERT clone but declined to release it: retrofitting the API is trivial, making one model good across wildly different tasks (e.g. Tetris) is not.

### Architecture, data, training (mostly inferred)

- Architecture is not public; his educated guess is something small and ModernBERT-like, which would explain the latency.
- Training data: the TypeSafe CEO says "100% of our data is synthetic (but not the type of crap that is just spit out from an LLM)". Raschka believes most of the effort went into curating that dataset, and cites an old collaboration where doubling hand-labeled data (from ~300 samples) beat days of hyperparameter tuning by 10–20 points.
- Training method: "Reinforcement Learning for Calibrated Decisions" (RLCD), proprietary. Closest published analogue is RLCR (*Beyond Binary Rewards: Training LMs to Reason About Their Uncertainty*, arXiv 2507.16806): reward `R = c − (q − c)²` where `c ∈ {0,1}` is correctness and `q` the model's stated confidence — i.e. RLVR plus a Brier penalty (an incorrect answer at 90% confidence scores −0.81; at 20%, −0.04; a correct answer at 90% scores 0.99).

### Calibration numbers

- RLCR vs RLVR + temperature scaling on HotpotQA: ECE **0.37 → 0.03** at similar accuracy (62.1% vs 63.0%).
- Six other datasets: average ECE **0.46 → 0.21**, accuracy **53.9% → 56.2%**.
- On the supervised side, adding a Brier term to cross-entropy for ModernBERT gave only a small extra calibration benefit (and worsened ECE on 1 of 9 datasets); the Brier term matters more in RL, where correctness is the only signal and cross-entropy is not already minimized.

### Use inside agent harnesses

Raschka's list of Jev applications for harnesses: pre-screening context for prompt injection, **selecting a model's reasoning-effort level**, selecting a `skill.md` from a registered skill library, acting as a judge for evaluation/self-refinement, and finding relevant files for context building. He does not expect Jev to unlock new capabilities — the win is making harnesses built around expensive GPT-6 / Opus 5.5 faster and cheaper.

### Clones and the open-weight gap

Hundreds if not thousands of Jev clones appeared within days, mostly ModernBERT/Qwen fine-tunes with SFT plus a Jev-like API; he likens them to Alpaca vs GPT-6. Tested alternatives: Contrastive Language Models 82.90% IMDb and fails the Tetris test; Laya 92.33% IMDb, also fails Tetris; GLiNER is directionally similar but weaker. An arXiv survey counted 2,170 Jev-related projects. The real demand for an open-weight equivalent is **privacy** more than cost. Reported weakness: legal reviews in non-English languages (workaround: bolt on a cheap translation model).

### Updates after publication

OpenAI announced a Jev-like **Decision API** at DevDay 2026 (Sep 29): "real-time decision-making by focusing Luna's intelligence on a specific set of user-defined questions with finite pre-defined answers", limited preview at announcement. Conclusion: the bar for justifying a custom fine-tune is now much higher, though high-volume single-task work still favors a specialist model.
